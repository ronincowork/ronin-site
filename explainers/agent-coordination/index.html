Explainers / Agent coordination

Do my Agents have to work as a team?

Independent by default. Coordinated when useful.

Agents can work side by side without talking to one another. When a job benefits from coordination, you choose the Routines and shared surfaces that support it.

The optional loop

Give work a shape without putting Agents in a box.

01

Work independently in separate sessions and worktrees.

02

Send a focused message when another Agent needs to act.

03

Use the team wipeboard for short-lived shared coordination.

04

Return durable results through documents and repository history.

This is a loop you may use, not a workflow Ronin forces. A session on no Team is a normal first-class session.

Routines

Choose the working behaviours a new Agent receives.

A Routine bundles related reading, SOPs, macros, actions, tools, and connections. Campaign defaults can be adjusted by a Team. The resolved choice is applied when a new Agent starts; flipping a switch does not rewrite an Agent already running.

  • Ronin BaseOrdinary macros, documents, work records, and session coordination.
  • Ronin ControlManaged repository desks, hand-in, team promotion, receipts, and Git guards.
  • Specialized RoutinesOptional methods or capabilities such as Machine, gbrain, Koshi, or Ronin Koe.

Coordination is not confinement

A message, wipeboard, prompt, worktree, or disabled Routine is not a security boundary. Session control dials govern Ronin's own reading and writing paths; they do not sandbox an Agent process. You remain responsible for the machine, accounts, and permissions the Agent can reach.
