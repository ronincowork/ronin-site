Explainers / Edges, Not Capabilities

What does Ronin actually do to my Agent?

Nothing inside. Everything at the edges.

Ronin does not alter your Agent's own capabilities. Its model, its prompts, its tools and how it does its work stay exactly as you set them. It shapes one thing: how an Agent meets other Agents and the house. Where work starts, where it goes when it is done, and what the Agent is told along the way. That is coworking, and it is all coworking is. If you read one page about what Ronin does, read this one.

The picture

Your Agent's world is its own. Ronin stands at the doors.

An Agent under Ronin is the same Agent you would run alone. Same provider, same account, same reasoning, same editor and terminal. Ronin never reaches inside that box. It puts a small number of doors on its boundary, each a plain command, and it tells the Agent what those doors are for.

How Ronin shapes an Agent

Three ways, and only three.

  1. Describe the method, at the edges.Ronin tells the Agent how to interact with others: where its work starts, where it goes when done, what to check when surprised. It never tells the Agent how to do its job. For a repository the whole method is three verbs: get a worktree, update it, hand it in.
  2. Expose edge tools.Each verb is one command that does one job and returns. The plain call is the clean path, so the Agent never has to remember the right base or the right cleanup. A tool never does a second job after its first. A second job worth doing is a second tool.
  3. Provide information.Every tool answers with an ack: what it did, the facts Ronin already holds about where the Agent now stands, and, when Ronin thinks the Agent should act, a nudge naming the tool. Nothing in an ack runs anything.

Independent by default

Start bare. Add only the coordination you want.

An Agent launched into Ronin with nothing switched on is a plain Agent in a plain checkout. Messaging, the team board, worktrees and a Team lead are separate, optional routines. Each one you turn on adds a door and the sentence that explains it, and nothing else. Turn it off and the door is gone.

Every routine is an offered path, not a lock. It says "here is how this house does it" and hands the Agent a command. The Agent may take the path or not. What Ronin will not do is reach past the door and make the Agent do it.

Coworking, defined

What coworking is, and what it is not.

Coworking iscoordination at the edgesCoworking is notcapability inside
ModelWhatever provider and account you chose. Ronin runs the CLI you already use.A model, a wrapper, a prompt library, or a "smarter" Agent.
WorkWhere work starts and where it lands: a private worktree, a hand-in, a lead's review.How the Agent writes code, tests, plans, or reasons.
ToolsA handful of edge commands: get, update, hand in, status, close.Tools for the job itself. Your Agent brings its own.
WordsAcks with facts and named nudges. Warnings where something could be lost.Gates, refusals, or actions taken for the Agent because it "should" have.
MemoryReceipts: what was handed in, promoted, closed, by whom, when.Persistent memory for the Agent, or a record of what it thought.
PublishingA pull request you review and merge.Anything that pushes to your remote by itself.

If a line in the right-hand column ever became true, Ronin would be taking over the work rather than coordinating it. That is the line Ronin does not cross.

Information, not automation

What an ack looks like.

This is the reply an Agent reads after handing work in. Every line is either what happened, a fact Ronin already held, or a nudge that names a tool. The Agent decides what to do with it.

ACCEPTED ronin_cowork:team/alpha/maya → team/alpha/dev  now 4f2a9c1e07  [hi_20260904104839_7f9d24]
  desk is level with the line
  base 51ce9424 · 0 behind dev · line is 3 ahead of dev; promotion due
  unsaved in this desk: none
  your lead is kenji
  NEXT: line moved; run tejun-desk status; if it reports a dev update, run tejun-desk sync
  NEXT: tell your lead with tejun-send kenji "..."

Nothing here ran on the Agent's behalf: no message was sent, no teammate's desk was touched, nothing was pruned. If the Agent wants any of that, each is one command away, and the ack said which.

Three rules under all of it

Honey, not sticks. Tools enable and warn. They refuse only where git itself cannot proceed. Two truths, everything else on loan. Your local working branch is what has been accepted; your remote release branch is what has shipped; every other branch, folder and record is temporary and has an owner. No orphaned edits with a dead owner. Every ending hands work on, lands it, quarantines it in plain sight, or discards it on purpose with a receipt. Read the no-behavioral-takeover promise.
