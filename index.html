What is Ronin Cowork?

A coworkspace around the Agents you already use.

Ronin puts live terminal sessions in one browser surface on a machine you control. Claude, Codex, Gemini, and other provider CLIs keep their own accounts, tools, reasoning, and normal way of working. Ronin adds the coworkspace around them.

01

Agents side by side

Run different provider CLIs beside one another and use each one through the account you already have.

02

Always-on sessions

Each Agent runs in a real tmux terminal. Close the browser and the session keeps working on the machine.

03

Workbench

Arrange terminal tiles and shared surfaces in independent workspaces. Each workspace keeps its own tabs and scroll.

04

Coordinate when useful

Keep Agents independent, or add direct messages, a team wipeboard, shared documents, and selected Routines when the work benefits from them.

05

Parallel file work

When selected for a reviewed repository, managed worktrees give Agents separate desks, hand-in, lead integration, and Git safeguards.

06

Make it yours

Choose and customize the reading, SOPs, Macros, Actions, tools, connections, and Routines offered to new Agents. Your versions live outside the repositories Ronin updates.

Why Ronin Cowork?

Why Ronin?

Your machine

It runs on your computer, home server, or virtual machine. If the machine is remote, you reach it through your own VPN, such as Tailscale.

Open source

Ronin Cowork is open source. View the code, change it, and use it for free.

Your accounts

Keep your accounts directly with the model companies and use your own subscriptions or API keys. Ronin does not resell model access and does not place itself between you and the provider.

Your work stays yours

Code and documents stay in ordinary repositories and files on your machine. Ronin does not relay Agent traffic or upload your code and conversations to a Ronin cloud.

Coordination without control

Ronin offers tools at the edges of cooperation. It does not become an Agent prompt engine, prescribe how an Agent reasons, or turn a working convention into a security boundary.

Ronin Services · Beta

Ronin Cowork works fully without them. Services are a separate, optional layer, and it is early days for this side.

Live work records

See what a session is doing, its progress, its repositories, and the documents it has listed without interrupting its work.

02

Readable transcripts

Readable transcripts are in development. They will turn terminal output into text for independent scrolling, mobile use, and session history.

03

Stats

See operating counts such as sessions, active days, Macros, and Agent minutes. Stats exclude code, prompts, terminal output, paths, filenames, and other free text.

Dictate into a terminal tile with your own Hotwords attached. Spoken summaries back are planned, not part of the current capability.

05

gbrain

Where Ronin fits

Keep the stack you chose. Add only the layer you need.

Ronin does not resell model access or replace your Agent, provider account, machine, repositories, or working method. It supplies the locally run coworkspace around them.

Start with a bare Agent in an always-on terminal. Add the Cowork floor, Ronin Base, or managed file coordination only when those tools help.

Explore beta Services separately as live work records, readable transcripts, Stats, Voice, and supported integrations become ready.

Removing Ronin does not require an export or migration. Your provider accounts still work, and your repositories and documents remain ordinary files where you put them.

Tech Talk

Terminal CLIs on your machine.

Ronin runs Agent applications as terminal CLIs on your machine. Claude Code, Codex, Gemini, and other Agents remain their own programs and communicate directly with their model providers under your account. Ronin is the coworking layer around those programs, not another model runtime.

01The sessions stay on the machine

Each agent runs inside a tmux session. tmux owns the long-running terminal process, not the browser. Closing the browser disconnects the view; it does not close the agent. As long as the Ronin machine and its tmux server remain running, the sessions continue there.

The browser reconnects to those same sessions. It does not start a replacement session in the browser and it does not move the terminal to a Ronin server.

02A virtual machine keeps the team available

A cloud virtual machine gives terminal agents an always-on Linux host for their repositories, tools, and persistent sessions. The agent models still run with their own providers, so a normal x86 VM with enough RAM is usually more useful than a GPU server.

You can use Hetzner, DigitalOcean, Akamai Cloud, Vultr, or another provider. The practical questions are how much memory the team needs, how you connect privately, and how the sessions survive after your laptop closes.

03The VPN is the security wall

By default Ronin binds to the machine's Tailscale address. If Tailscale is absent, it falls back to the local machine only. It does not expose Ronin Cowork to the public internet by default.

Tailscale is the security wall. You can open Ronin Cowork from any device on your Tailscale network without exposing it to the public internet or adding another Ronin login. If you choose to expose Ronin more broadly, it requires a password or passkey.

04Locked mode is the live terminal

Locked mode is the default and comes standard with Ronin Cowork.

In locked mode, the browser tile is attached directly to the tmux terminal through a WebSocket. Terminal output is rendered by the terminal emulator, and keyboard, pointer, and scroll input are sent back to that live terminal.

That directness has a consequence people do not expect: terminal scroll is terminal input. Scrolling from a phone or laptop changes the live terminal's screen and scrollback on the remote machine. The browser is operating a terminal that may be a thousand miles away; it is not independently scrolling a web document.

Because locked mode repaints a live remote terminal, it can feel noticeably laggy on a slower connection.

05Unlocked mode is a recorded text view

Unlocked mode is a beta Ronin Services capability and is not generally available yet.

Unlocked mode does not attach a second terminal client. Ronin's record service reads the session tape, reconstructs the settled output into a scroll, and renders that stream to a plain scrollable browser view. Input still goes back to the active tmux pane, but reading and scrolling no longer drive the terminal's own viewport.

This makes the recorded view behave more like people expect a browser to behave:

  • Scroll through earlier output without moving the live terminal screen.
  • Read over a higher-latency connection without repainting a remote terminal for every movement.
  • Use the session more comfortably on a phone.
  • Preserve a transcript beyond the terminal's current visible scrollback.
  • Keep readable terminal history beyond the current scrollback.

The unlocked transcript is reconstructed from terminal output. Terminal applications can repaint and overwrite their screen, so the recorded view folds those updates into readable text rather than claiming to be a pixel-perfect recording of every historical screen.

If the record service is not installed or available, the unlocked view is off and Ronin Cowork falls back to the locked live terminal.

06What leaves the machine

Ronin Cowork does not send the project workspace to an external Ronin surface. The agent CLIs still communicate with their own model providers, just as they do when run without Ronin.

If you opt into Ronin Services, you may choose to share anonymous operating measurements through Ronin's single outbound channel. The file and receipt stay on your machine. It excludes project files, code, prompts, terminal output, and transcripts. Declining sends nothing.
