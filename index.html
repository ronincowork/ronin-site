What is Ronin Cowork?

Ronin owns the shared edges, not the agent's mind.

Ronin is not a harness! It is a agent management system. It provides the sessions, terminals, Roster, jobs, groups, handoffs, and coordination between agents. Claude, Codex, Gemini, and the others keep their own reasoning, memory, personality, and native way of working.

Use your own account directly with agent providers, including Claude, Codex, Gemini, Hermes, and Grok.

02

Side by side

Let agents work side by side and get the benefit of each one's strengths. They communicate directly or over a shared wipeboard.

03

Roster

Use the Roster to see progress and group related agents.

04

Session jobs

Start new sessions with preset job descriptions.

05

Macros

Use prebuilt macros so agents can communicate and coordinate.

06

Make it yours

Customize the jobs, macros, SOPs, and skins. Make your own, share them, or download them from the Ronin library.

Why Ronin Cowork?

Why Ronin?

Your machine

It runs on your computer, home server, or virtual machine. If the machine is remote, you reach it through your own VPN, such as Tailscale.

Open source

Ronin Cowork is open source. View the code, change it, and use it for free.

Your accounts

Keep your accounts directly with the model companies and use your own subscriptions or API keys. Ronin does not resell model access and does not place itself between you and the provider.

Your data

Ronin is local software that works with your sessions and project files but does not access or share your data remotely. Your data doesn't leave your machine unless you share it, for example with a model provider.

Make Ronin your own

Make Ronin your own. Customize session jobs, macros, SOPs, and skins. Make your own, share them, or download them from the Ronin library.

Ronin Services

As a companion to Ronin Cowork, Ronin Services solve additional problems.

Cowork does not need Services in order to function. These capabilities require ongoing maintenance, updates, third-party integrations, and selected open-weights models:

01

Progress ladders

Session progress ladders monitored and kept current by Koshi, a Ronin custom agent assistant.

02

Voice

Voice output that reads session activity back to you. Voice input can use Ronin's Whisper-based option or your own dictation tool.

03

Session recording

The recording captures what each terminal prints and turns it into readable text for scrolling, voice, and session summaries.

04

Memory

Ronin memory saves lessons, which can be recalled by future sessions working on the same project and session job.

gbrain, Garry Tan's open-source agent brain, adds broader external memory across connected sessions.

05

Usage

See how frequently you use: sessions started and ended, active days, macros run, and agent minutes. They do not include prompts, code, paths, filenames, session names, or other free text. Anonymous leaderboard comparisons are optional.

06

Locked and unlocked

Locked mode is the default and comes standard with Ronin Cowork. Unlocked mode is an additional utility and comes optional with Ronin Services. Locked mode is the direct live terminal. (Tldr: Unlocked mode renders the recorded session output like browser content. Unlocked mode makes it easier to use on mobile, scroll independently, read aloud, summarize, and save as a transcript.)

Ronin is not trying to profit from reselling access to other companies' models or by putting a toll in front of open-source Cowork running on somebody's own machine.

The longer-term commercial direction may be infrastructure and maintained intelligence around cowork services. Though we don't know for sure but we are just having fun for now. For example:

Tech Talk

Terminal CLIs on your machine.

Ronin runs the agent applications as terminal CLIs on the Ronin machine. Claude Code, Codex, Gemini, and the other agents remain their own programs and communicate with their model providers under the owner's account. Ronin is not an AI harness providing agentic services it is the co-working layer around those programs; it is not another model runtime.

01The sessions stay on the machine

Each agent runs inside a tmux session. tmux owns the long-running terminal process, not the browser. Closing the browser disconnects the view; it does not close the agent. As long as the Ronin machine and its tmux server remain running, the sessions continue there.

The browser reconnects to those same sessions. It does not start a replacement session in the browser and it does not move the terminal to a Ronin server.

02The VPN is the security wall

By default Ronin binds to the machine's Tailscale address. If Tailscale is absent, it falls back to the local machine only. It does not expose Cowork to the public internet by default.

Tailscale is the security wall. You can open Cowork from any device on your Tailscale network without exposing it to the public internet or adding another Ronin login. If you choose to expose Ronin more broadly, it requires a password or passkey.

03Locked mode is the live terminal

Locked mode is the default and comes standard with Ronin Cowork.

In locked mode, the browser tile is attached directly to the tmux terminal through a WebSocket. Terminal output is rendered by the terminal emulator, and keyboard, pointer, and scroll input are sent back to that live terminal.

That directness has a consequence people do not expect: terminal scroll is terminal input. Scrolling from a phone or laptop changes the live terminal's screen and scrollback on the remote machine. The browser is operating a terminal that may be a thousand miles away; it is not independently scrolling a web document.

Because locked mode repaints a live remote terminal, it can feel noticeably laggy on a slower connection.

04Unlocked mode is a recorded text view

Unlocked mode is an additional utility and comes optional with Ronin Services.

Unlocked mode does not attach a second terminal client. Ronin's record service reads the session tape, reconstructs the settled output into a scroll, and renders that stream to a plain scrollable browser view. Input still goes back to the active tmux pane, but reading and scrolling no longer drive the terminal's own viewport.

This makes unlocked mode behave more like people expect a browser to behave:

  • Scroll through earlier output without moving the live terminal screen.
  • Read over a higher-latency connection without repainting a remote terminal for every movement.
  • Use the session more comfortably on a phone.
  • Preserve a transcript beyond the terminal's current visible scrollback.
  • Feed settled text into text-to-speech and session summaries.

The unlocked transcript is reconstructed from terminal output. Terminal applications can repaint and overwrite their screen, so the recorded view folds those updates into readable text rather than claiming to be a pixel-perfect recording of every historical screen.

If the record service is not installed or available, the unlocked view is off and Cowork falls back to the locked live terminal.

05What leaves the machine

Core Cowork does not send the project workspace to an external Ronin surface. The agent CLIs still communicate with their own model providers, just as they do when run without Ronin.

Ronin Services sends routine usage measurements as a small report through Ronin's single outbound channel. A copy and receipt stay on your machine afterward. The report excludes project files, code, prompts, terminal output, and transcripts. Anonymous leaderboard participation is an additional choice.
